# 从 v1.8.1 迁移

## 1. 程序与配置

旧项目保留，新版解压到独立目录。新版使用 PyQt6，不再导入 PySide6。第一次启动前按 README 建立Python环境。

若希望沿用旧界面设置，把旧项目的 `settings.ini` 复制到新版解压目录，**从这个目录启动**。原键名沿用，已有Tag尺寸、偏移、相机profile、RGB参数、Home和界面设置可以继续读取。`run.bat` 已自动切到脚本目录。

安装为 wheel 后，`apriltag-upper` 使用当前工作目录的 `settings.ini`，避免向site-packages写用户设置。嵌入时可以显式传 `MainWindow(settings_path="...")`。

旧INI里的标定路径可能是旧电脑的绝对路径；如果文件不存在，在标定面板重新选择即可。程序不会因为找不到旧文件就静默套用另一份文件。有保存路径时尊重所选路径；全新配置才默认展示包内参考文件。

SDK自定义宿主用的 `sdk_settings.json` 与旧INI是不同格式，不直接互换。SDK配置里的标定路径也需在同事电脑存在。移动文件后重新调用 `load_calibration()` 并保存配置即可。

## 2. 迁移保持的计算约定

- AprilTag 36h11，彩色图像，未启用深度测距。
- 检测最多缩到宽960，再回到原图做角点细化与IPPE_SQUARE求解。
- Tag中心位置按ID保留5次观测中值；旋转使用当前帧；目标偏移按Tag局部坐标旋转。
- Legacy模型保持：Pan绕z，Tilt轴/符号/零位来自文件，外参平移用米。
- 文件原值与编辑副本分开，选择原值时副本编辑不会影响当前计算；导出到新目录。
- 两份标定来源字段只是历史说明，不用文件名/路径/来源哈希判断“配套”。文件自身类型/数值仍必须正确。
- Home与模型零位互不替代；Encoder只监视，Base仍用Cmd。

用于恢复“某一份文件的编辑副本”的内容指纹仍保留。它只防止源文件内容变化后把旧编辑副本错误套回，与两份标定文件是否配套无关。

## 3. 新SDK与完整界面的差别

完整界面保留旧工作方式：当前Cmd控件值参与最新识别结果的Base计算，包括离线查看/手动调整。新 `results_updated` 接口反映的就是这个显示状态。

高层 `AprilTagSystem` 给每帧附上主机接收时的Cmd快照；未知Cmd时不输出Base。它不会仅因连接串口就假定云台在90/90，需本次连接实际调用过 `command()`。外部图像模式可以由调用者明确提供Cmd。这些值仍只是指令空间，不是曝光同步的实际角度。

界面识别工作线程与SDK Locator共同使用 `DetectorEngine`；相机格式转换、RGB参数与串口实现也共用。完整界面以QThread桥接，纯SDK以Python线程运行；两者不要同时持有同一设备。

## 4. 新增接口与行为

- wheel/sdist分发，支持Python3.8与3.14两套固定依赖。
- 无Qt、无RealSense也能导入核心SDK并处理外部图像。
- 返回结构化结果：每ID Camera/Base毫米坐标、角点、旋转、重投影误差、帧序号、主机时间戳。
- 可复用PyQt6面板、Qt轮询桥、拥有内存的QImage转换。
- 完整界面增加 `results_updated` 和带时效检查的 `result_snapshot`，便于宿主拿坐标。
- 相机连续5次取帧失败会退出并报错，避免无限等待。SDK停止/错误后清空可用结果。

## 5. 重新确认设备

软件侧测试不连接真实设备。本机仍需验证：D435实际profile与USB带宽、RGB可写范围、串口端口和反馈、静止Tag定位、长按释放、退出后设备重开。对比坐标时确保Tag边长、Cmd、所选计算来源、标定、每ID偏移和中值开关一致。
